# Temporal storage and engine v1 on any date (Phases C1 and C2)

Generated by `python -m chiocca.v2.invariante` from `docs/invariante_numeros.json`. Do not edit by hand: a test compares this file with the script output. Aggregate numbers only; the only companies named are those of the ground-truth cases, which are public.

## The store

- Parquet queried through DuckDB (`chiocca/v2/armazem.py`), built offline from `data/brutos/cvm` (checked by hash) and the ENET cache, in `data/armazem/`, outside git. Fiscal years 2010 to 2023; no sealed fiscal year goes in.
- Tables: `versoes` (12,372 DFP versions, with the filing date), `contas` (7,550,842 rows, from open data and from 342 ENET documents), `fca` (22,203 versions), `cadastro` (2,679 rows) and `escalas` (original scale of each open-data statement). `manifesto.json` keeps the SHA-256 hash of every source file.
- For documents filed after 2024-12-31, the store keeps metadata only: version, filing date and the structure, that is, which statements exist and their type (consolidated or individual), with no account and no value (decision of 2026-11-09: the structure counts as metadata). Documents filed after 2024-12-31 with only their structure in the store, by fiscal year: 2023: 14 (total: 14). Engine v1's `como_era` uses this structure of the latest version to know whether a consolidated statement exists (the ENET route, amendment 8) and to name the ENET cash flow statement; with a reference date up to 2024-12-31, that version's values are never read, and a test ensures no account or value of these documents is stored.
- `FontesArmazem` has the same interface as the raw files (`chiocca.cvm.Fontes`): engine v1 runs on the store without any change.

## Engine v1 on the date

- `ExercicioNaData` (`chiocca/v2/na_data.py`): one company in one fiscal year, as it was on the reference date, with the version used, only the versions filed by the date, the origin (open data or ENET) and the document link. The date goes through the 2011-04-30 to 2024-12-31 range, and the fiscal year through the seal.
- Cross-section on the date: the same study 1 functions (`como_era`, `grupos`, `sinais_amostra`), with the year's deciles recomputed only with the companies whose version was public on the date.
- When the version used is not the latest, `como_era` reads the structure of the latest version, filed after the date (study 1 behaviour, amendment 8). The lineage records: "structure read from a document filed after the date (study 1 behaviour, amendment 8)". On each fiscal year's cut-off date, this happened in 531 company-years from 2010 to 2023.
- Product layer, next to the engine and without changing any of its values: the `produto_nao_calculaveis` column lists the signals the product shows as "not computable" because of an unfilled balance sheet.

## Phase C2: scale, evidence and ENET fetching

- `escala_original` of the version used: from open data, 13,760 versions in MIL, 1,050 versions in UNIDADE. The ENET cache keeps values already in reais and does not record the page's scale; for ENET versions, the field is empty, with that reason in the lineage.
- Contract evidence: each DFP line read becomes an `Evidencia`, with a stable id, document (version, filing date, origin, address and hash), statement, column, account, official description, value in reais and, with the `Localizador`, the source file and line.
- ENET fetching through a separate command (`python -m chiocca.v2.buscar_enet YYYY-MM-DD`): it lists the versions the date needs that are not in the store, fetches only those (consolidated, released fiscal years, filed by 2024-12-31) and rebuilds the store. No query fetches anything.

## Restatement through the following year's comparative on 2024-12-31

**Descriptive analysis.** Study 1 and engine v1 do not change. Rule of 2026-11-09 (`docs/en/contracts.md`, section 4): when the DFP of t+1 is already public on the date, each account of t in the version used is compared with the PENÚLTIMO column of t+1 (same statement, same code, same type); a difference above R$1,000 per account goes into the investigation as evidence, with the text "different value in the following year's comparative (restatement or reclassification)". Because of the seal, fiscal year 2023 has no comparison.

On 2024-12-31, 5,747 of 8,084 comparable company-years (from 2010 to 2022) have at least one account with a difference above the tolerance.

Materiality (rule of 2026-11-09, `docs/en/contracts.md`, section 4): a highlighted difference is one in a total or key line (total assets, current liabilities, non-current liabilities, equity, net revenue, net income and operating cash flow) above 1% of total assets of the version used; the others (reclassifications between lines and smaller differences) stay only in the full list of evidence. ## How to reproduce

```
python -m chiocca.v2.armazem      # builds data/armazem from data/brutos/cvm and data/cache/enet
python -m chiocca.v2.buscar_enet 2024-12-31 --listar   # versions the date needs that are not in the store
python -m chiocca.v2.invariante   # invariant and cross-section on the maximum date; writes this document
python -m chiocca.v2.invariante --so-comparativo   # redoes only the following year's comparative
```
